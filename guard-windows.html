Set it up in four steps

You do not need to edit the scripts. The exact Layers Guard Chrome Web Store ID is already shown in the command below.

All four files should be together in the same folder.
Step 01

Create a folder and download the toolkit

Create a folder such as Layers-Guard-Windows inside Downloads. Use the buttons above to save all four PowerShell files into that same folder.

  • Do not rename the files.
  • Keep the restore script with the backup created later.
  • Install Layers Guard from the Chrome Web Store first.
Search for PowerShell, then choose “Run as administrator”.
Step 02

Open PowerShell as Administrator

Open the Windows Start menu, search for PowerShell, right-click Windows PowerShell, and choose Run as administrator. Approve the Windows User Account Control prompt.

🔐
Use the parent's administrator password.

The child's Windows account should remain a Standard User so these machine policies cannot simply be changed back.

A successful run prints green-style [PASS] lines in PowerShell.
Step 03

Run the hardening command

First move PowerShell into the folder where you saved the files. Then run Layers Guard using its published Chrome Web Store ID.

Set-Location "$HOME\Downloads\Layers-Guard-Windows" .\layers-guard-harden.ps1 -ExtensionId 'alielgklefmocpmnmfahepacngmeomof'

If Windows says script execution is disabled, run Set-ExecutionPolicy -Scope Process Bypass in that same Administrator PowerShell window, then run the hardening command again. This changes the policy only for the current PowerShell process.

After restarting Chrome, verify the policies rather than assuming setup succeeded.
Step 04

Restart Chrome and verify protection

Close every Chrome window and reopen Chrome. Then run the checker and review Chrome's policy page.

.\layers-guard-check.ps1 -ExtensionId 'alielgklefmocpmnmfahepacngmeomof'
  • Open chrome://policy and use “Reload policies” if needed.
  • Confirm Guest Mode, Incognito, Add profile and extension Developer Mode are unavailable.
  • The checker lists Windows Administrators. Confirm the child's account is not listed.
// What success looks like

Verify, don't just assume

Expected protection checks

The checker should report these controls as configured. If it warns about multiple Chrome profiles, review and remove or secure old profiles manually—the toolkit deliberately never deletes user data.

✓ Guest Mode disabled
✓ Incognito disabled
✓ New Chrome profiles disabled
✓ Extension Developer Mode disabled
✓ Layers Guard force-install policy present
✓ Windows Secure Mode marker present
// Important limits

Windows Secure Mode strengthens Chrome

It is an important extra layer, not a whole-device parental-control system.

What this toolkit protects

It applies machine-level Google Chrome policies, makes common Chrome bypass routes harder to use, can force-install the published Layers Guard extension, creates a policy backup before changes, and provides a read-only checker plus conservative rollback.

What it does not protect

It does not control Edge, Firefox, Brave, Opera, portable browsers, games, native apps, other devices, DNS/router settings, or a child who has Windows Administrator access. For broader coverage, combine Layers Guard with a Standard child account and OS/router parental controls.

Need to restore the previous policies?

Keep the automatically created layers-guard-policy-backup.json beside the scripts. In Administrator PowerShell, run:

.\layers-guard-restore.ps1

Restore is intentionally conservative: if another administrator changed a targeted setting after setup, the script warns and leaves that newer value untouched rather than overwriting it.
